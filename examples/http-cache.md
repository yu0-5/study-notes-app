# HTTP 缓存学习资料

## 强缓存

浏览器缓存资源后，如果仍在新鲜期内，可以直接使用本地缓存，不必向服务器验证。
响应头 `Cache-Control: max-age=3600` 表示资源在规定的新鲜期内可被复用。
具体是否复用还取决于请求缓存策略等因素。

## 协商缓存

缓存需要验证时，浏览器可以携带 `If-None-Match`，其值来自上次响应的 `ETag`。
服务器比较资源版本，如果没有变化，可以返回 `304 Not Modified`，浏览器继续使用已有响应体。
如果资源发生变化，则返回新的内容及缓存相关响应头。

## 容易混淆的指令

- `no-cache`：允许存储，但复用前需要成功验证。
- `no-store`：要求缓存不要存储该请求或响应。
- `private`：响应面向单个用户，不能由共享缓存存储。

## 练习

1. 强缓存与协商缓存分别在哪个环节减少网络开销？
2. 为什么 `no-cache` 不等于“不保存缓存”？
3. 如何用浏览器 Network 面板观察缓存命中与 304 响应？
